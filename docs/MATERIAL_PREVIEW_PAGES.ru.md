# Предпросмотр образцов материалов на GitHub Pages

[English](MATERIAL_PREVIEW_PAGES.md)

Для каждого подходящего одноцветного филамента создаётся процедурный образец WebP на основе числового цветового ориентира и типового некалиброванного PBR-профиля линейки. Один просмотрщик Three.js WebGL работает в открытой панели деталей; сотни контекстов WebGL на сетке каталога не создаются.

## Подтверждения и ограничения

- Приоритет: опубликованный HEX физического печатного образца, затем HEX производителя/каталога, затем один непрозрачный образец RGBA.
- При отсутствии числового цвета он остаётся неопределённым, а изображение не выдумывается.
- Многоцветные и градиентные записи сохраняют документированные образцы цветов вместо выдуманных 3D-полос.
- Типовые карты нормалей и шероховатости имитируют микротекстуру; физическое совпадение цвета, измеренный BRDF, направление слоёв и фактический Fusion Render не заявляются.
- Прозрачные материалы и материалы с частицами остаются приближёнными.

## Конвейер

После проверки каталога `tools/build_demo.py` создаёт PBR-карты и вызывает `tools/generate_material_previews.py` для создания WebP в `dist/assets/material-previews`. Пути записываются в `catalog.json`, количество — в `meta.counts.material_previews`.

Исходник статического просмотрщика — `demo/material-viewer.js`. CI собирает размещённый на том же сайте ES-модуль с закреплёнными версиями Three.js и esbuild из `package.json`. Сборка проверяет все ссылки на файлы предпросмотра и модуль. Развёртывание GitHub Pages остаётся ручным согласно настройке репозитория.

## Направление дизайна

Существующий графитовый интерфейс с приглушённым шалфейным цветом остаётся без изменений. Визуальный акцент — реалистично выглядящий образец; статус источника и фактические числовые образцы цветов остаются видимыми. Оформление следует рекомендациям Damir Sokolovsky по дизайну unslop: https://github.com/heydamir/unslop (CC BY 4.0).

## Локальная сборка

    python -m pip install 'jsonschema>=4.21,<5' 'numpy>=2,<3' 'Pillow>=11,<13'
    python tools/build_demo.py --out dist
    npm install --no-audit --no-fund --package-lock=false

Для локальной проверки модулей и загружаемых текстур используйте HTTP-сервер статических файлов.

## Оценочная оптическая прозрачность (схема v1)

`appearance.transmission` — числовой визуальный параметр PBR в диапазоне [0,1], наследуемый пресет → линейка → цвет и при необходимости переопределяемый на отдельных уровнях. Это **не** альфа-канал производителя и не измеренная доля прошедших фотонов. Существующие `ior` и `attenuation_distance_mm` задают оценки преломления и оптического поглощения; `opacity:255` остаётся независимой альфой.

Два встроенных типовых профиля — полупрозрачный PLA (transmission 0,40, haze 0,80, длина поглощения 7,5 мм) и полупрозрачный PETG (transmission 0,55, haze 0,55, 12 мм). Bambu PETG Clear переопределяет визуальный профиль PETG значениями transmission 0,75, haze 0,35 и расстоянием затухания 75 мм. Все эти числа помечены **filamentra_estimate**; значения линейки или цвета могут заменить их при наличии значимых подтверждений источника.

Статический генератор предпросмотра и интерактивный WebGL-просмотрщик моделируют эталонную **толщину стенки 2 мм** с официальным изображением монограммы 4FusionLab позади образца. Полупрозрачные материалы показывают монограмму в разной степени, непрозрачные закрывают её. Результат качественный, а не калиброванное физическое предсказание. WebGL-просмотрщик переводит расстояние затухания из миллиметров в единицы сцены образца и использует `attenuationColor` Three.js для окраски проходящего света. Сохранённый HEX цвета остаётся отдельным от оценочной оптики.

Образцы производителя Clear, такие как `#00000000`, не имеют числового цвета красителя. Только для рендеринга такого *подтверждённого полностью прозрачного экранного образца* используется нейтральный оттенок (`#F6F9F7`), без записи выдуманного HEX или заявления о физических измерениях цвета. Все остальные неизвестные цвета по-прежнему остаются без предпросмотра.

## Фирменный оптический ориентир 4FusionLab

Исходный ресурс `demo/assets/brand/4fusionlab-logo.svg` — **точная копия** официального знака организации 4FusionLab из `4FusionLab/.github/assets/avatar.svg` (владелец репозитория тот же; замена, созданная ИИ, не используется). `tools/build_demo.py` растеризует его в PNG 512 × 512 для загрузчика текстур Three.js. Генератор Python WebP помещает тот же SVG фиксированного размера 176 × 176 пикселей позади образца размером 30 мм. Непрозрачные предпросмотры полностью закрывают монограмму внутри модели; полупрозрачные показывают её пропорционально приближённым пропусканию и оптическому затуханию. Фон одинаков для всех филаментов, поэтому эффекты можно сравнивать напрямую.

Сборка CI проверяет наличие и возможность декодирования растеризованного логотипа, а также проверяет, что монограмма создаёт различимые тона внутри прозрачного образца. CairoSVG необходим только при сборке; опубликованный сайт остаётся статическим.

## Рендеринг оптики с учётом haze

Поле `haze` (0..1) внешнего вида версии 1 — некалиброванная оценка потери деталей изображения сквозь FDM-пластик, отдельная от `transmission` (количества света). Генератор WebP применяет нормализованное размытие Гаусса только к логотипу 4FusionLab **за силуэтом**, не затрагивая окружающий фон или затенение поверхности. Просмотрщик Three.js приближает haze повышением шероховатости *прошедшего света* с помощью независимой созданной карты. Поскольку `MeshPhysicalMaterial` использует эту шероховатость и для отражений, WebGL не может точно имитировать физическое объёмное рассеяние. Оба просмотрщика учитывают переопределения пресет → линейка → цвет. То же нормированное поле экспортируется для Fusion, где адаптер сообщает о снижении точности, а не заявляет незаметно, что воспроизводит haze.
