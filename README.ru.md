## Что хранится в репозитории?

**Filamentra DataSource** — каталог данных для [Filamentra](https://github.com/4FusionLab/Filamentra), будущего аддона Autodesk Fusion от **4FusionLab**.

Аддон позволит выбирать реальные филаменты и устанавливать соответствующий **визуальный Appearance** в текущий проект Fusion по запросу. В этом репозитории находятся **данные каталога**, а не интерфейс и не код аддона.

- **Производители:** названия брендов и подтверждающие ссылки.
- **Линейки:** тип полимера, фактура и заявленные особенности.
- **Цвета:** официальные названия, постоянные ID, цветовые референсы и происхождение значений.
- **Доставка:** версионированные, прошедшие проверку архивы каталога через GitHub Releases.
- **Независимость:** справочник не должен зависеть от Autodesk Fusion.

## Структура каталога

```text
catalog/
├── brands/
│   └── <manufacturer>/
│       ├── brand.json
│       ├── <product-line>.json
│       └── ...
└── schema/
    └── line.schema.json

docs/
├── CATALOG_FORMAT.md
└── DISTRIBUTION.md
```

Один JSON на линейку со всеми её цветами. Иерархия — **производитель → линейка → цвет**; полимер, фактура и эффекты хранятся как атрибуты для фильтров, а не как дополнительные уровни папок.

Подробнее — в [описании формата](docs/CATALOG_FORMAT.md).

## Качество важнее количества

- **Только реальные продукты.** Не выдумываем линейки, цвета и артикулы.
- **Проверяемость.** Предпочитаем информацию производителя, фиксируем источник и дату проверки.
- **Оценки отдельно от фактов.** HEX с сайта и фото катушки не гарантируют точного совпадения с отпечатком.
- **Постоянные ID.** Переименование оттенка не должно ломать ссылки на него.
- **Визуальный материал — не инженерный.** Каталог не заменяет достоверные физические свойства для расчётов.
- **Права на контент.** Не копируем фотографии и текстуры производителей без разрешения.

## Релизы и совместимость

Версия наполнения каталога отделена от версии схемы JSON:

| Элемент | Назначение |
| --- | --- |
| Релиз каталога (`vX.Y.Z`) | Новые и исправленные данные |
| Версия схемы (`1`, `2`, …) | Формат, понятный аддону |
| `catalog-index.json` | Версии, совместимость, архивы и контрольные суммы |
| `catalog-schema-vN.zip` | Снимок каталога в конкретном формате |

Аддон должен выбирать **последнюю совместимую** версию и хранить локальный кэш для работы без сети. Обновление каталога не должно самопроизвольно менять уже установленные Appearance в существующих моделях.

**Статус: планирование / первоначальное оформление репозитория.** Наполненного каталога, проверенного механизма публикации и готового набора данных пока нет. Структура и формат распространения — проектные решения до реализации и тестирования. Подробности — в [документе о доставке](docs/DISTRIBUTION.md).
